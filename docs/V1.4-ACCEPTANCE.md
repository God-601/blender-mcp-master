# v1.4.0 live acceptance suite — real Blender MCP / agent clients

**Status: pending external execution.** These are test instructions, **not results**. Passing GitHub Actions and bpy wheel fixtures cannot prove a particular agent follows the skill or models professionally. Do not mark PASS without artifacts and a human/visual reviewer.

## Controlled A/B setup

1. Save disposable starting scene `baseline.blend`. Store SHA-256, Blender version, installed addon and MCP tool schemas; note client and model.
2. For each task use the same source scene copy and prompt. Variant A: same agent + Blender MCP with skill not loaded; Variant B: skill activated. Preserve all failed attempts.
3. Record the actual agent usage counters *only when the client exposes them*, along with MCP calls, repeated file reads, full script bytes sent, time and crashes. Do not infer tokens from file size.
4. Keep three captures from identical front, side and three-quarter camera positions, plus detail/wireframe when necessary. Record capture hashes and separate human/reviewer notes.
5. For each output, run scene baseline comparison, evaluated geometry/budget checks, visual review and export validation. Never equate Blender GLB roundtrip with Roblox or another engine import.

## Explicit modeling scenarios

### V14-01 — measured chair / contact

Prompt: "Create a low-poly medieval oak chair suitable as a static game prop, 0.50 m wide, seat at 0.45 m high, four physical legs and 1,500 evaluated triangles maximum. Ask only the remaining important visual design questions before building; preserve all pre-existing objects."

Acceptance: four legs physically support the seat, no accidental floating/severe penetration, expected silhouette and triangulated budget, actual screenshot comparison, preserved source-scene identity.

### V14-02 — reference sword / silhouette

Prompt: "Create a stylized fantasy longsword matching the supplied orthographic reference. Preserve the intended blade, guard, grip and pommel silhouette. Use owned objects, clean planar hard-surface surfaces and verify with identical front/side/three-quarter captures."

Acceptance: reviewer finds correct key landmarks and joints, no arbitrary X triangulations on editable panels, reasonable material/UV seams. Cannot PASS reference match without an actual user-supplied image and inspected Blender captures.

### V14-03 — low-poly tree / game budget

Prompt: "Build a realistic-looking stylized game tree for Roblox, no more than 2,000 evaluated triangles, with a lightweight PBR material and a plausible silhouette from 3 angles. Reuse supplied constraints; ask only unknown visual choices."

Acceptance: measured triangle count, branches support crown, no floating canopy, compact materials and valid pivots; source image and render masks can optionally be fed into `reference_silhouette_compare.py` **only** if alpha-isolated, identically framed PNGs.

### V14-04 — modular architecture / protected objects

Prompt: "Create a low-poly medieval gatehouse with two towers, a doorway and snap-compatible walls. Keep all unrelated scene assets untouched. Match declared scale and use clear ownership, with tests for wall seams and door clearance."

Acceptance: source and new collections compared via baseline, non-destructive scene preservation, no unintended overlap or incorrect gap, real inspection images.

### V14-05 — fault injection

Introduce a broken/floating leg in a duplicated test scene; request a minimal correction without touching other objects. Test a simulated MCP timeout after an attempted mutation. Agent must inspect actual scene identity/state **before** retrying and must never claim crash recovery without saved checkpoint evidence.
