# Recorded acceptance tests — 8 November 2026

This is evidence from the available Blender, Roblox Studio and Godot setup.
Unity and Unreal were unavailable and are **not validated**. This record is not
a declaration that every 2.0 release gate passed or that a release was published.

## Actual production A/B exercise

`integrations/agents/production_benchmark.py` ran five controlled cases
(chair, sword, tree, modular wall and source-backed tube retopology), three
trials per arm: **30 actual Codex CLI generations**. Each case reopened one
shared canonical .blend; all six builds for that case used the same bytes.
Real thread IDs, raw prompts, guide hashes and provider usage were retained.
Final checks found no triangle-budget, topology, UV/material-presence or
selected-source-preservation issues in the 30 builds. Actual Godot 4.4.1
imported all 30 GLBs with matching triangle counts and UV/material surfaces.

| Recorded usage | Baseline | With skill and guide |
| --- | ---: | ---: |
| Logical trials | 15 | 15 |
| Input tokens | 523,182 | 555,603 |
| Output tokens | 2,424 | 2,781 |
| Cached input tokens (included in input total) | 56,064 | 0 |
| Total input + output | 525,606 | 558,384 |

The candidate used **6.236% more total tokens** in this constrained exercise.
This is not evidence of savings, pricing or general performance superiority.
The provider did not emit its model identifier; identical CLI/default settings
do not independently prove identical backend models. Cache usage also differed.

The adapter guarantees mandatory parts, creates UVs/materials and performs
exports. The agents choose bounded parameters; they do not independently execute
freeform Blender/MCP production in this exercise. Materials are simple nodes;
this A/B does not validate arbitrary image-based PBR, rigging, artistic quality
or a correction loop. The retopology case really bridges ordered source-backed
rings, relaxes interior vertices and projects to a supplied source. Surface
accuracy is sampled inside target triangles; no continuous global error bound
is claimed. Five representative three-quarter views were actually inspected;
there was no blind artistic scoring of all 30 assets.

Initial provider quota errors and adapter failures are retained in attempt
archives. Latest logical-trial counts must not erase those failures. Summary
metadata separates archived attempts and deduplicates usage by actual provider
thread; unknown usage on failed requests is not counted as zero. After adapter
fixes, successful generations were reused with their original prompts/receipts,
and geometry was rebuilt without paying for duplicate provider generations.

## Recovery, writer exclusion and transport restart

`test_native_recovery.py` killed only its owned background Blender child,
then reopened a real checkpoint. Owned state, protected sentinel and original
source bytes were recovered. The test exposed a per-process writer-lock gap.
The native host now uses a shared source-path-keyed OS lock (`msvcrt` on Windows,
`flock` on POSIX), releasing on close/crash while retaining the lock inode.
A competing process on the same source was rejected; a process after the kill
reacquired the same lock without deleting it or guessing PID liveness.

`test_addon_reconnect.py` launched only its own hidden GUI Blender, with the
installed addon 1.8/protocol 15 on a private loopback port. Ping/data requests,
client reconnect, server stop/restart and sentinel preservation passed. The
process exited normally. This exercises actual addon JSON/TCP transport, not
a full MCP/JSON-RPC client. Native identity remains process-scoped across
transport restarts; an embedding client must still re-probe its transport.

The reports explicitly record a base revision, dirty-source state and actual
tested source hashes. They must not be presented as release-tag exact-SHA
certification. The scripts are opt-in: CI does not start paid provider trials
or assume that the local addon is installed.

## Actual Roblox Studio import, appearance and physics

Testing used a user-prepared empty place and the official Studio MCP. No
desktop UI control was used for the test. Upload permissions were requested
through the normal Assistant settings; no API keys or permission workaround
were used. Three synthetic chair model assets were uploaded for comparison.
No experience was published by this test.

The first GLB imported ten MeshParts with the expected dimensions, but scalar
shader color was lost and the model appeared gray. An image-based PBR variant
created ten SurfaceAppearances with all four maps. Initial map loading failed,
then succeeded; the first image encoding nevertheless appeared too dark.
Explicit linear-to-sRGB encoding of the constant base-color fixture produced
the expected visible brown result. Normal/roughness/metalness data maps stayed
linear. The before/failed/corrected captures are retained.

`integrations/roblox/constant_pbr_fixture.py` reproduces that narrow conversion
in a separate background Blender. It refuses linked/nonconstant shaders and
existing outputs; it is not a general shader bake or an instruction to gamma
convert existing image textures a second time.

The test declared a scale of four studs per source unit; this is a fixture
policy, not an engine hard limit. A seat ray hit at approximately Y=1.92.
In a real server playtest, a collidable probe settled at Y=2.0635 with zero
speed; an otherwise identical noncollidable probe passed below the seat.
The probes were removed and Studio returned to Edit. This verifies the
controlled seat location, not all possible contact points, LODs or FPS.

## Remaining scope limits

No Unity/Unreal certification, universal artistic approval, rig/animation engine
round-trip, full freeform-agent benchmark or same-model cost claim is supported
by this campaign. Preserve these limits when describing the product or deciding
on a release. Existing exports/guides remain available for untested targets.
