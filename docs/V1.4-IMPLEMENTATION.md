## Implemented in the current candidate branch

- Export input validation: refuse repeated or invalid object names before mutating scene objects, and reject mismatched filename extensions before writing files. Does not resolve real engine import.
- New read-only `scripts/modeling_scorecard.py`: explicit per-criterion status plus evidence references; missing evidence can never turn into PASS, and the scorecard does not certify artistic quality or engine import.
- Regression tests for export validation (requires bpy for runtime cases) and scorecard contract (pure Python).

## Release-quality conditions

1. Use **saved identical scene fixtures** and recorded reference images before and after agent execution.
2. Run the Python static suite, bpy runtime matrix, mutation campaign, Node tests, npm pack, nonpublishing ZIP readiness and clean-install checks. No test results should be marked PASS unless logs establish it on the exact commit.
3. Run real client/MCP tasks: chair with four ground contacts, fantasy sword matching orthographic reference, low-poly tree with strict budget, modular architecture with snap seams and a protected-scene editing case. Inspect front/side/three-quarter views plus close-ups where relevant.
4. Verify input question behavior: only missing consequential requirements, reuse previously answered values; no repeated kickoff on refinements or crash recovery.
5. Record errors, skipped trials, crashes, retries, permissions, scene-preservation baselines and actual token usage **only when the provider exposes it**.
6. Validate reported geometry and exports in the actual destination application where available. Blender-to-Blender roundtrip alone is not target-engine certification.
7. Use independent visual review. If no real images are available, return NOT VERIFIED; a reviewer receipt is not a pixel classifier.
8. Prevent changes to unrelated source objects, user files, rigged meshes and shared datablocks without explicit authorization and a rollback plan.

## Scorecard fields

`silhouette`, `proportions`, `topology`, `component_fit`, `uv_materials`, `optimization`, `scene_preservation`, `export_destination`.

Each takes `status` in `PASS | ISSUE | N/A | NOT VERIFIED` and `evidence` as a list of supporting artifact IDs or paths. A `PASS` without a referenced observation is downgraded to `NOT VERIFIED`. The script intentionally reports `artistic_quality: NOT VERIFIED` and `engine_certification: NOT VERIFIED` regardless of supplied metadata. Reuse `scripts/visual_review_report.py` and `scripts/visual_evidence_manifest.py` for separate evidence handling.

## Complete design scope for v1.4.0 (approved planning backlog)

All tasks below are **planned work**, except those explicitly marked implemented. An approved CI does not turn planned tasks into completed features.

### A. Reference Match and visual quality (#44; P1)

1. Accept user-supplied reference image(s) and document provenance, license, relevant intended view and orthographic/perspective assumptions.
2. For each source reference, create a matched inspection view from the **actual Blender model**, fixing projection, framing, scale landmarks, camera pose and neutral lighting where possible. Do not invent missing reference camera metadata.
3. Compare **silhouette, negative spaces, component completeness, proportions and visible shading**. Measurements from image processing are only proxies; human or image-capable reviewer decisions must reference actual captures.
4. Produce a defect list with stable object IDs, severity, view, source/capture paths, suspected cause, proposed minimum edit and reviewer identity.
5. Correct owned/duplicated components, then recapture the same views; mark unresolved or unavailable visual evidence NOT VERIFIED.

**Required acceptance fixtures:** a missing chair leg, a misplaced sword guard, an off-silhouette tree crown, a wall with an incorrect doorway and a shading artifact. At least one intentional artistic deviation must not be incorrectly auto-rejected. **No automated artistic PASS from metadata, hash, AABB or scorecard alone.**

### B. More precise geometry, contacts and topology (#45; P1)

1. Make the intended relationship explicit for each object pair: `surface_joint`, `intentional_embed`, `no_penetration`, `clearance`, `articulated_connection`; record tolerances in scene units.
2. Preserve fast AABB rejection and BVH broad-phase triage. Evaluate narrow-phase candidates on disposable evaluated meshes; distinguish closed solids, open surfaces, fully contained geometry, coincident faces, coplanarity and degenerate triangles.
3. Report contact candidates, measured clearance or penetration only where mathematically justified; return REVIEW/NOT VERIFIED where the algorithm is inconclusive.
4. Inspect flat X-like triangulation, internal redundant faces, normals, UV boundaries, smoothing and shared datablocks before any topology edits.
5. Apply fixes only on owned copies, record pre/post evaluated triangle counts and scene/object baselines; do not automatically delete unknown interior faces.

**Required acceptance fixtures:** face touching, edge-only contact, separated leg, overlapping cubes, fully nested box, concave shell, non-manifold open sheet, intentional tenon, UV seam and deforming surface. Record false-positive/false-negative limits.

### C. Adaptive Workflow and the question contract (#46; P2)

1. Select expert routes by destination + geometry + visual style + deformability + required evidence, not just by keyword. Route to a small set of relevant references and scripts.
2. For a new design, ask only unanswered **consequential** questions; preserve user answers, brief, creative delegation and selected technical budgets. Run a second interview round only when a consequential blocker appears.
3. On follow-up edits, error recovery, retopology and exports, do not restart the kickoff. Changes to protected objects, destructive operations and paid actions remain separate consent gates.
4. Define consistent but backwards-compatible script result envelopes: explicit targets, created/modified owned objects, actual measurements, uncertainty, warnings, errors, rollback/checkpoint and source-version metadata.
5. Record tool-schema changes after reconnection; do not call undocumented MCP tools. Selective references and concise checkpoints are preferred over expanding the root SKILL.md.

**Required acceptance fixtures:** complete brief, incomplete tree brief, delegated design, existing-project correction, absent MCP visual tool, changed tool schema and a forced mid-operation error.

### D. Scorecard, Defect Memory and Benchmark Arena (#47; P2)

1. **Implemented (candidate):** evidence-gated, read-only `scripts/modeling_scorecard.py` covering silhouette, proportions, topology, component fit, UV/materials, optimization, scene preservation and destination export.
2. Add links from each score entry to actual machine report, view/image, baseline, reviewer and criteria/threshold version. Reject fake artistic or engine certification.
3. Reuse the technique-registry opt-in approach for Defect Memory: `defect_id`, symptom, affected object IDs, root cause, correction, before/after evidence, reviewer and reproducible test. Only reviewed successes may be reused. Do not automatically persist or upload private project data.
4. Benchmark the same agent and model **with/without skill**, and later v1.3 vs v1.4, using identical fixtures, reference images, Blender version, plugin version, tool settings, seed and evaluation rubric.
5. Record all trials, including failure/crash, retries, operations on protected objects, real tool calls, elapsed time and tokens **only if exposed**. Visual scores require a reviewer blind to variant whenever feasible.

**Required acceptance fixtures:** missing evidence cannot PASS, a technical ISSUE overrides incomplete fields, a false reviewer receipt cannot become pixel verification, registry corruption must never be silently overwritten, and benchmark output must keep failed attempts.

### E. Safety, portability and release engineering (P0/P1, cross-cutting)

- **Implemented (candidate):** `scripts/export_asset.py` refuses repeated/invalid export target names and mismatched format/extension before scene/filesystem modifications.
- Test source-scene preservation, explicit ownership, invalid/missing targets, no implicit whole-scene fallback, transactional export overwrite and recovery after simulated failures.
- Keep a versioned compatibility matrix for agents, MCP tool schemas and Blender Python versions. CI bpy execution does not certify an agent's client integration.
- Validate optional npm resource-server read-only boundaries, path allowlisting and fresh ZIP installs with SHA256. Never assume npm publication has occurred.
- Use CI Python, Blender bpy matrix, mutation tests, Node, npm packaging, release readiness; check exact PR commit after every update.
- A new feature can ship with a documented NOT VERIFIED limitation **only if its core promise is not advertised as verified**.

## Implemented follow-up on v1.3 base (integrated branch, 2026-11-05)

- **v1.3 base merged:** PR #42 squashed to main as `72ba6d805e399799e77203c23c0adbe716b21be3`. Tagged v1.3.0 release has NOT been created by this work.
- **v1.4 integration:** PR #50 is based on the new `main`, avoiding the #49 conflict after merging #42. PR #49 is superseded as an integration target; its code changes were ported, not force-merged.
- **Lower initial context:** `SKILL.md` was compacted from approximately 15,967 UTF-8 bytes to below 10.5 KB, with full file-name discovery, explicit safety and nonredundant kickoff preserved. This is a **byte difference**, not measured client token savings. Read references only by need.
- **Safe export:** reject duplicate/invalid object names and extension/format mismatch before scene/file mutation. Added static + bpy tests.
- **Scorecard:** `scripts/modeling_scorecard.py` accepts evidence-tagged technical criteria, never infers visual or engine approval.
- **Adaptive router:** `scripts/workflow_router.py` selects one primary guide and explicitly required secondary guides, and skips design questions on continuations; no implicit scene access.
- **Reference silhouette metrics:** `scripts/reference_silhouette_compare.py` reads actual PNG RGBA alpha pixels with bounded decoding and SHA-256, compares matching masks by intersection-over-union, and ALWAYS requires independent visual review. It cannot interpret arbitrary photographic references or judge artistic quality; it refuses opaque images and unsupported formats.
- **Component fit:** `scripts/inspect_component_fit.py` adds bounded world-space evaluated surface vertex-to-BVH distance samples. Sampling is **not** exact collision detection or proof of full contact/containment.
- **Defect Memory:** existing `scripts/technique_registry.py` accepts reviewed `defect_resolution` records with before/after evidence and explicit consent to persist; older technique fingerprints remain backwards-compatible.
- **Benchmark evidence:** `scripts/agent_efficiency_compare.py` also reports repeated reference reads, full script bytes, visual captures and failed tool calls when the client supplies those metrics. No billed-token savings or art superiority inferred.
- **Tests:** added pure Python tests for router, scorecard, image mask decoder and reviewed defect records; added Blender runtime tests for export guards and sampled fit evidence. Full automated CI and manual client tests are distinct gates.

## Limits that cannot be validated from repository CI alone

- No direct access to a real connected Codex/Claude/Cursor session using Blender MCP and user reference images. Thus **real agent behavioral compliance and actual token savings remain NOT VERIFIED**.
- No actual import sessions in Roblox/Unity/Godot/Unreal; in-engine fidelity is NOT VERIFIED.
- A transparent PNG alpha mask metric is not reference-photo interpretation or artistic quality assessment.
- A surface BVH sample cannot prove exact watertight contact, safe boolean operations or no penetration.
- Do not publish a version labeled complete while these core promises lack real proof; release only completed bounded features with accurate scope after checking all exact-commit workflows.

## Measurable A/B benchmark contract

Use the same agent, model, prompt SHA, source scene SHA, Blender/MCP versions, same image references, tool configuration and outcome rubric. Record input/output tokens only where actually reported by the client. Record failures, full/partial reference bytes, executed script bytes, output summaries, visual checkpoint hashes and preservation evidence. Run `scripts/agent_efficiency_compare.py` on paired evidence files; report token savings only when both usage sources are present, comparable and complete. Screenshot evaluations require actual reviewer inspection.
