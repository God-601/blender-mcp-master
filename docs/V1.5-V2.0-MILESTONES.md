# Blender MCP Master — v1.5 → v2.0 delivery ladder

**Engineering milestones, not published releases.** The package still identifies
its last published/release-ready version until explicit acceptance gates are
met. A green bpy/Node/Godot CI does NOT prove artistic quality, consumer agent
behavior, or Roblox/Unity/Unreal imports. Never claim a milestone "shipped"
only because its supporting tooling was merged.

## 1.5.0 — PBR & UV production

**Included engineering candidate:** `scripts/pbr_channel_audit.py`, a
read-only, explicit-mesh inspection of UV presence, Principled BSDF channel
connections, actual image sources/availability and likely non-color map
colorspace mismatches. Works with bpy 4.2–5.2 test fixtures; complements
`pbr_material.py`, `uv_diagnostics.py`, `uv_island_gutter_audit.py`.
Does not render textures, unwrap UVs, bake PBR maps, inspect arbitrary
shader groups or guarantee external-engine fidelity.

**Remaining release gate:** reference projects with hand-reviewed atlas and
trim sheets, baked normal/AO/roughness maps actually saved, texel density
evidence, real UV seam/gutter measurements and independent visual check.
Test that base material and protected scene stay unchanged.

## 1.6.0 — Game-ready delivery

**Included engineering candidate:** `scripts/game_delivery_manifest.py`,
a pure evaluator of *authored* (not platform-hardcoded) triangle, material and
texture budgets and untrusted external engine-import receipts. The existing
`game_asset_preflight.py` measures evaluated triangles/pivots/materials in
bpy, and Godot CI now imports a real Blender-authored GLB. No promise of
Roblox/Unity/Unreal support is made from that Godot result.

**Remaining release gate:** actual Studio/engine imports with screenshots,
surface normals/tangents, pivots, UV/materials/collision and LOD checks; real
targets and measurable triangle/performance budgets; separate rigged-export
workflow. Read platform constraints from current official docs.

## 1.7.0 — Specialist reviews

**Included engineering candidate:** `scripts/specialist_review_gate.py` to
normalize independent reviews across geometry, visual, materials, export and
scene safety, flag missing reviewers/evidence, and prevent a model builder's
self-reported PASS from counting as independent validation. It does NOT spawn
parallel subagents or inspect actual image pixels; artifact authenticity
requires external verification.

**Remaining release gate:** real Codex/Claude subagent routing on tasks with
controlled tokens, rate limits and failure recovery, and independent reviews
of actual model captures; compare single-agent and multi-specialist quality.

## 1.8.0 — Benchmark Arena & cost discipline

**Included engineering candidate:** `scripts/benchmark_suite_summary.py`
aggregates only matched, completed, scene-preserved A/B trial records and
keeps crashes, incomplete runs, missing usage and differing fixtures in the
report as inconclusive. It cannot observe provider usage or certify quality
from JSON alone. Existing `agent_efficiency_compare.py` handles each pair.

**Remaining release gate:** at least three runs per fixture across chair,
sword, tree, architecture and retopo/rig task using same model, prompt, scene,
MCP version; real token records where client exposes them; blind image review
where feasible. Report variability, failures and quality tradeoffs.

## 1.9.0 — Release candidate & migration

**Included engineering candidate:** `scripts/release_gate_report.py`
checks consistency of explicit milestone version, exact 40-character SHA,
review evidence and artifact statuses; **never** authorizes/publishes a release.

**Remaining release gate:** versioned npm/ZIP reproducibility, SHA-256,
clean-install tests on Codex/Claude/Cursor, policy for old workflow archives,
change log, migration guide, rollback and actual user approval.
No v1.9 publication solely on technical CI.

## 2.0.0 — Integrated 3D production

Combine validated milestones into a modular pipeline with consistent
contracts for assets, scene identity, explicit ownership, specialist
delegation, material bakes, geometry/retopo, visual correction, and actual
engine import. Promote a capability to "supported" only with an end-to-end
acceptance fixture and reviewer evidence. Preserve published-version
compatibility or provide a documented migration.

### Version merge and publishing policy

1. Integrate *code* in small, CI-green PRs; do not force legacy conflicting
   branches or silently rewrite published releases.
2. Each milestone receives its **own readiness record**; a merged feature
   foundation is not a stable version tag.
3. Actual package version, GitHub Release and optional npm publication are
   separate, authorized actions after exact-SHA CI and external acceptance.
4. Maintain the nonpublishing default; report `NOT VERIFIED` for anything
   that would require an unavailable agent, image, Blender session or engine.
5. Never infer rate-limit savings from fewer bytes loaded in SKILL.md.
