# v1.4.0 quality gates and real-client integration

This document distinguishes repository-tested diagnostics from external validations. The
Blender MCP Master resource MCP is read-only; it does **not** operate a live
Blender process. Use a separately connected Blender-control MCP.

## Feature-to-evidence mapping

| Feature | Automated support | What still needs an actual execution |
| --- | --- | --- |
| Visual reference matching | RGBA mask IoU, bounding boxes, centroids, disagreement; PNG CRC/dimension and hash guards | Real capture with matching framing and reviewer judging reference/photo, shading and style |
| Component fit | Explicit AABB/BVH, surface distance and additional closed-surface ray parity containment candidates | Closed manifold guarantees, visual joint quality and physical contact |
| Adaptive workflow | `plan_blender_workflow` read-only MCP tool; selects specialty guides and missing brief topics | Agent consistently uses recommendations without repeated questions |
| Quality / Defect Memory | Evidence-only Scorecard, explicit reviewed opt-in corrections | Independent evaluator and permission to retain local history |
| Token economy | Compact `SKILL.md`, lazy catalog, paired JSON metrics comparator | Actual provider usage data for matched skill-off/on sessions |
| Game export | Source preflight + Blender GLB roundtrip; Godot 4 headless GLB importer probe | Actual invocation of Godot, screenshot/shader validation and other engine tests |
| Scene preservation | Read-only probes, ownership gates and rollback fixtures | Real saved .blend recovery when the agent/tool crashes |

## Godot import probe

The executable integration lives in
[`integrations/godot/`](../integrations/godot/README.md).
It calls Godot's `GLTFDocument.append_from_file` and
`generate_scene` in headless mode, returning actual geometry/UV/material
presence metrics. This is the **only** supported target-engine automated
smoke harness here; an actual Godot binary must run to obtain evidence.

## Unity, Unreal and Roblox Studio

These require external editor processes and their respective importers.
No importer run means **NOT VERIFIED**, regardless of Blender roundtrip:

- **Roblox Studio:** import exported static mesh, inspect Studio MeshPart size/orientation,
  material or SurfaceAppearance, UVs and collision fidelity. Capture Studio screenshots.
- **Unity:** import FBX/GLB through an explicitly supported importer; inspect transforms,
  materials/shaders, UVs, triangles, collision and play-mode appearance.
- **Unreal:** inspect StaticMesh import settings, scale, material assignment, collision,
  lightmap UVs and Nanite suitability (if relevant).
- **Godot:** use the supplied probe for import parseability, then separately inspect
  imported 3D scene and camera images.

Avoid inventing hard engine polygon or material limits. Read current platform
documentation before certifying version-specific requirements.

## Real skill effectiveness

The CLI scripts cannot monitor Codex/Claude account usage or call the user's
local Blender from GitHub Actions. Execute [V1.4 acceptance](V1.4-ACCEPTANCE.md)
in an actual connected agent environment. Preserve tool logs, image captures,
scene hashes, incidents, and token usage where available. Compare paired records
using `scripts/agent_efficiency_compare.py`, not estimates of token savings.

## Never claim

- "Quality passed" based only on image-mask IoU or metadata hashes.
- "No penetration" based solely on AABB/BVH/ray parity candidates on complex solids.
- "Compatible with all agents" from just documentation and tests.
- "Engine import verified" without a source-linked external editor execution.
- "Reduced usage by 61%" because the SKILL.md bytes dropped ~61%.
